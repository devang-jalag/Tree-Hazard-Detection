==================================================
1. PRODUCT GOAL
==================================================

The application helps city arborists determine which tree complaints should receive an inspection first.

The system should:

- Read complaint descriptions
- Identify potential hazards
- Calculate an explainable priority score
- Rank complaints from most urgent to least urgent
- Highlight uncertain complaints requiring human review
- Allow an arborist to inspect an individual complaint
- Generate a printable Hazard Assessment Poster

The system must NOT claim that a tree is definitely dangerous. It is a prioritization and triage tool for deciding which complaints should receive human inspection first.

4. PRIORITIZATION ENGINE
==================================================

Implement a deterministic and explainable scoring system.

Every component must produce a score from 0–100.

FINAL SCORE:

finalScore =
    dangerScore * 0.50 +
    waitScore * 0.25 +
    locationScore * 0.15 +
    reviewScore * 0.10

Round finalScore to the nearest integer.

--------------------------------------------------
4A. DANGER SCORE — 50%
--------------------------------------------------

Analyze complaintText using keyword and phrase matching.

Add points for hazards:

+30 leaning / significantly leaning
+25 falling / fallen / uprooted / unstable
+20 house / home / building / roof threatened
+15 car / vehicle / driveway threatened
+15 power line / electrical wire / utility line
+10 trunk splitting / split trunk / cracked trunk
+10 large dead branch / hanging branch / broken limb
+10 storm damage
+5 blocking road / street
+5 blocking sidewalk

Cap dangerScore at 100.

Also produce a list of the exact hazards detected.

Example:

complaint:
"Tree is leaning toward my house and power line."

Detected hazards:

- Leaning tree
- Property threat
- Power line threat

dangerScore should be high.

--------------------------------------------------
4B. WAIT TIME SCORE — 25%
--------------------------------------------------

Longer waiting complaints should receive higher scores.

Normalize waiting time using:

waitScore = min(daysWaiting / 180 * 100, 100)

Therefore:

0 days = 0
90 days = 50
180+ days = 100

--------------------------------------------------
4C. LOCATION IMPACT — 15%
--------------------------------------------------

Major/high-traffic Halifax streets should receive higher scores.

Major streets:

Barrington Street = 100
Spring Garden Road = 100
Quinpool Road = 90
Robie Street = 90
Gottingen Street = 85
Oxford Street = 80
Windsor Street = 80
Almon Street = 80
Chebucto Road = 75
Dutch Village Road = 75

Normal residential streets = 40

Quiet/local side streets = 25

Use the street associated with each complaint to determine locationScore.

--------------------------------------------------
4D. HUMAN REVIEW — 10%
--------------------------------------------------

The system must identify complaints where the description is vague or insufficient.

Examples:

"Tree looks weird."

"Something seems wrong with the tree."

"Tree needs attention."

"Please check this tree."

If a complaint is vague or contains insufficient information:

reviewScore = 100
reviewStatus = "Unsure"

Otherwise:

reviewScore = 0
reviewStatus = "Reviewed"

IMPORTANT:

"Unsure" is NOT the same as "dangerous."

It means the system lacks sufficient information and wants a human arborist to inspect/review it.
